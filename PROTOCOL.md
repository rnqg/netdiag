# Протокол узла, версия 1

Управление использует HTTPS. Заголовок `Authorization: Bearer TOKEN` обязателен для всех путей. Перенаправления не поддерживаются. Клиент проверяет сертификат и не передаёт токен другим origin.

## Управление

`GET /v1/capabilities` возвращает `version`, `udp_port`, `http3`, `max_bytes`, `max_seconds`, `max_streams`, `udp_no_fragment_ipv4`, `udp_no_fragment_ipv6`.

`POST /v1/session` принимает JSON с положительными `max_bytes` и `seconds`. Узел ограничивает запрос своими максимумами и возвращает:

| Поле | Значение |
| --- | --- |
| `id` | 16 случайных байт, hex |
| `key` | 32 случайных байта, hex; ключ аутентификации UDP |
| `expires` | Срок действия, Unix time в секундах |
| `max_bytes` | Бюджет тестовых данных сессии |
| `udp_port` | Порт UDP на том же адресе |

Сессия привязывается к адресу TCP/QUIC-клиента. `X-Forwarded-For` не используется. Адрес UDP должен совпадать с ним. Клиент закрепляет последующие запросы за фактически использованным адресом узла, чтобы повторное разрешение DNS не направило сессию на другой экземпляр.

`POST /v1/ID/close` закрывает сессию. После истечения срока или закрытия данные не выдаются. Ключи и сессии хранятся только в памяти.

## Передача данных

`GET /v1/ID/download` выдаёт `application/octet-stream` без сжатия. Ответ ограничен остатком бюджета и временем потока. Размер не обещается через Content-Length.

`POST /v1/ID/upload` принимает поток и возвращает JSON `received_bytes`. Клиент различает данные, переданные HTTP-транспорту, и число байт, подтверждённое получателем. Неподтверждённая отдача не выдаётся за успешное измерение скорости.

Один поток ограничен 25 секундами и сроком сессии. До восьми одновременных потоков. Контрольные запросы сессий и заголовки транспорта не входят в бюджет тестовых данных. Консервативное резервирование блоков может завершить передачу немного раньше полного лимита.

Для нагрузочных потоков клиент открывает отдельные TCP-соединения HTTP/1.1. Несколько HTTP/2 stream не считаются несколькими TCP-потоками. HTTPS API также доступен через HTTP/2 и HTTP/3.

## UDP

Дейтаграмма имеет длину 60..1472 байт:

| Смещение | Длина | Содержимое |
| --- | --- | --- |
| 0 | 4 | ASCII `NDG1` |
| 4 | 16 | Бинарный ID сессии |
| 20 | 8 | Sequence, unsigned big-endian |
| 28 | 32 | HMAC-SHA256 |
| 60 | Остаток | Тестовое заполнение |

HMAC считается ключом сессии по конкатенации диапазонов `[0:28]` и `[60:]`. Узел возвращает неизменённую дейтаграмму только после проверки сессии, срока, источника и HMAC. Ответ не больше запроса. Ограничение — 20 допустимых пакетов в секунду на сессию. Бюджет учитывает запрос и ответ.

Время отправки и приёма берётся на клиенте с монотонных часов. Ключ и внутренние отметки не нужны в отчёте. Протокол измеряет RTT; синхронизация часов и односторонняя задержка не заявляются.

Для нагрузки используется отдельная сессия UDP-контроля. Клиент резервирует ей часть общего пользовательского бюджета. Исчерпание лимита или срока сессии помечает измерение ограниченным, а не доказывает сетевую потерю.

Запрет IP-фрагментации запрашивается через API ОС клиента и узла и сохраняется в результате. Значение `fragmentation=disabled` требует подтверждения обеих сторон; `request_only` означает запрет только на клиенте. Успех определённого размера подтверждает проходящий размер UDP payload на этом пути. Неудача большего размера не устанавливает точный PMTU: возможны фильтрация, временные потери и иные причины.

## Ошибки

HTTP 400 — неверный запрос; 401 — токен; 403 — сессия или источник; 404 — неизвестный путь; 429 — предел сессий или потоков. Клиент не делает из этих кодов вывод об отсутствии интернета.
